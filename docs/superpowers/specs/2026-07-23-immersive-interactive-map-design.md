# 灵境智导大屏沉浸式互动地图设计

## 文档状态

- 日期：2026-07-23
- 状态：已完成逐节讨论并获得用户确认
- 当前实施范围：第一阶段“大屏沉浸式导览与基础 AI 画像路线”
- 目标页面：`/visitor/map`

## 目标

将现有互动地图从“地点标记与路线查询工具”升级为比赛现场的大屏智慧导览舞台。页面先播放约 78 秒的电影式灵山经典巡游，再平滑进入可自由操作的智慧地图；正常情况使用高德 3D 地图与 Loca 动效，网络地图不可用时自动切换本地摄影与矢量场景，巡游进度、字幕和讲解不中断。

本设计同时表达三类价值，但分阶段交付：

1. 第一阶段：大屏视觉冲击、自由探索与基础 AI 画像路线。
2. 第二阶段：面向手机现场游览的定位、签到、印章和互动问答。
3. 第三阶段：结合天气、拥挤度、停留时间和实时状态进行深度动态规划。

本轮实施计划只覆盖第一阶段，第二、三阶段仅保留扩展边界，不提前建设未确认的数据系统。

## 已确认的关键决策

- 主要设备是比赛现场大屏电脑，移动端本轮只保证基础可访问。
- 采用“引导式互动”：先播放 60–90 秒电影巡游，再进入自由探索。
- 采用在线高德地图加本地降级场景，网络异常不能中断演示。
- 采用方案 C“动态聚焦舞台”：巡游时保持地图全景，接管后再从边缘展开信息面板。
- 经典巡游路线为：灵山大照壁、九龙灌浴、灵山大佛、灵山梵宫。
- 巡游时数字人以灵境光球和本地语音轻量陪伴，仅在关键站点短暂展开讲解卡。
- 默认巡游使用本地预编排路线、字幕和音频；评委接管后才使用真实 AI 和实时路线服务。
- 自由探索提供老人舒缓线、亲子趣味线和摄影光影线。
- 采用“分层导演架构”，不新增比赛专用地图路由，不复制第二套地图页面。

## 非目标

- 不在第一阶段实现游客实时定位、签到、勋章、AR 或多人互动。
- 不在第一阶段接入实时客流、排队时长或新的第三方数据源。
- 不缓存、下载或打包高德地图瓦片。
- 不修改现有 AI、实时语音、WebSocket、会话或地图后端协议。
- 不让默认巡游依赖实时 AI、实时 TTS 或付费路线请求。
- 不以复杂 3D 模型重建整个灵山景区。

## 用户体验

### 进入与启动

互动地图首次进入时保持可理解的静态舞台，显示经典路线轮廓与单一主按钮“开始灵境巡游”。地点和本地降级资源在后台并行加载。用户也可以跳过巡游直接进入自由探索。

高德地图在 5 秒内成功初始化时使用在线 3D 场景；否则直接使用本地场景。无论选用哪一种场景，启动按钮、时间线和巡游内容保持一致。

### 78 秒经典巡游

| 时间 | 站点或阶段 | 镜头与视觉 | 讲解行为 |
| --- | --- | --- | --- |
| 00–06 秒 | 湖光启幕 | 湖面倒影溶解为 3D 鸟瞰，经典路线微光显现 | 不讲话，让画面建立空间感 |
| 06–17 秒 | 灵山大照壁 | 低空推近，灵境光球首次出现 | 约 8 秒本地语音，不展开数字人卡 |
| 17–32 秒 | 九龙灌浴 | 半环绕水景，路线光效产生水波扩散 | 约 11 秒语音，讲解卡展示约 8 秒 |
| 32–50 秒 | 灵山大佛 | 从山脚向上抬升，光线与音乐达到峰值 | 约 14 秒语音，核心数字人讲解卡展开 |
| 50–66 秒 | 灵山梵宫 | 画面转为暖金，镜头平缓落位 | 约 11 秒语音，讲解卡展示约 8 秒 |
| 66–78 秒 | 交还控制 | 路线回收为全景，画像入口与面板展开 | 用一句话邀请评委选择下一段体验 |

巡游控制固定提供：

- `Space`：暂停或继续，镜头、音频、字幕和时间轴同步冻结。
- `Esc`：跳过，以短过渡进入自由探索，而不是直接卸载舞台。
- 点击地图：提示用户是否接管；确认后停止自动镜头。
- “重新巡游”：从自由探索状态重置并再次播放。
- 页面进入后台：自动暂停，返回后由用户继续。

开启“减少动态效果”时不执行镜头飞行、旋转或路径脉冲，只使用静态取景与短淡化，但保留时间轴、字幕和站点内容。

### 轻量数字人陪伴

`LingjingOrb` 是巡游中的主要 AI 视觉形态。它使用暖金与湖绿色表达状态：待机、讲解、思考、可提问和错误降级。光球可以沿路线移动，但不承担地图坐标计算。

抵达九龙灌浴、灵山大佛和灵山梵宫时，`ScenicStoryCard` 从侧边短暂展开。讲解结束后卡片自动收起，让地图继续成为视觉主体。自由探索状态下，点击光球可以打开现有 AI 导游入口或轻量问答面板。

默认巡游音频由本地静态资源提供，并配套完整字幕。音频不可播放时自动切换字幕讲解，不调用实时 TTS 兜底。最终比赛验收要求本地音频文件齐全；开发测试允许使用静音占位和字幕。

### 自由探索

巡游结束后页面从全景舞台转为三层结构：

- 中央地图继续占据主要面积。
- 左侧按需展开当前行程和站点顺序。
- 右侧按需展开 AI 推荐理由与应用按钮。
- 灵境光球保留在地图右下方，承担提问入口。
- 时间轴收缩为“重新巡游”与当前模式指示。

自由探索支持：

- 点击地点标记后镜头聚焦，并显示景点或美食摘要。
- 将地点加入当前行程。
- 通过行程列表调整站点顺序，再统一请求路线。
- 在应用新路线前进行预览，展示路线差异和推荐理由。
- 应用路线后允许撤销到上一个稳定版本。
- 保留现有详情抽屉、景点/美食图层和步行/驾车能力。

### 画像路线

三种画像改变路线排序权重，而不只是替换颜色：

| 画像 | 主要权重 | 演示表达 |
| --- | --- | --- |
| 老人舒缓线 | 较少站点、较短连续步行、休息弹性、室内外平衡 | 强调节奏舒缓和可随时缩短 |
| 亲子趣味线 | 动态体验、故事性、用餐便利、儿童注意力节奏 | 优先九龙灌浴等趣味节点，并安排弹性用餐点 |
| 摄影光影线 | 当前时段、开阔视野、倒影、建筑光影 | 用拍摄顺序与时段理由解释路线变化 |

选择画像后的流程固定为：

1. 旧路线柔和淡出。
2. 新路线以流光方式预绘。
3. 展示三条简短推荐理由。
4. 用户确认后应用，或者取消并恢复旧路线。

三种画像各自包含一条随前端发布的精选路线，用于立即预览。真实 AI 在评委接管后生成优化建议；超时或失败时直接采用精选路线，并显示非技术化提示，不阻塞操作。

## 分层导演架构

### 总体结构

```text
MapView
├── useTourDirector            唯一时间轴与模式状态源
├── SceneAdapter
│   ├── useAmapScene           在线 3D 地图、Loca 和自由探索
│   └── OfflineScenicStage     本地摄影、SVG 路线和预制镜头
├── LingjingOrb                光球与 AI 入口
├── TourTimeline               巡游进度和控制
├── ScenicStoryCard            站点讲解卡
├── PersonaRouteSwitcher       画像选择与路线预览
└── 现有详情抽屉与路线 API
```

`MapView` 只负责加载地点、组合模块和保留当前业务入口。所有巡游时间和模式变化由 `useTourDirector` 管理。UI 组件订阅导演状态，不直接操纵地图；在线与离线场景实现同一套场景命令。

### `useTourDirector`

导演状态至少包含：

```text
mode: idle | touring | paused | exploring
elapsedMs: number
activeStopId: string | null
sceneKind: amap | offline
takeoverRequested: boolean
```

`fallback` 不是独立运行模式，而由 `sceneKind: offline` 表达；因此离线场景仍可处于巡游、暂停或自由探索状态，避免状态含义互相覆盖。

导演公开的行为包括：

```text
start()
pause()
resume()
skip()
requestTakeover()
confirmTakeover()
restart()
switchScene(kind)
```

导演使用单一单调时钟计算 `elapsedMs`，不能让每个组件独立创建定时器。暂停时记录已播放时长，继续时重建时钟基准，从而避免浏览器调度延迟累计。

### 场景适配器

在线与离线场景统一实现以下语义命令：

```text
initialize(context)
setCamera(cameraCue, options)
drawRoute(routeCue, progress)
focusPlace(resolvedPlaceId, options)
setActiveStop(stopId)
enterExploreMode()
resize()
destroy()
```

在线适配器基于现有 `useInteractiveMap` 演进，保留标记、地点选择和路线绘制，并新增 3D 相机与 Loca 动效。离线适配器使用项目自有摄影背景、CSS/SVG 覆盖物和预制镜头参数。两者都不能保存巡游进度；进度只存在于导演层。

### 组件边界

- `LingjingOrb`：接收导演与语音状态，发出“打开 AI”事件。
- `TourTimeline`：接收总时长、当前时长、站点和模式，发出暂停、跳过、接管和重播事件。
- `ScenicStoryCard`：只展示当前站点内容，由导演控制出现和收起。
- `PersonaRouteSwitcher`：管理画像选择、预览确认与撤销，不直接请求地图实例。
- `OfflineScenicStage`：只实现离线场景，不复制行程、AI 或画像业务。

新增文件应保持单一职责，单个实现文件原则上不超过 800 行；`MapView` 应继续作为薄组合层。

## 数据契约

### `TourDefinition`

```ts
interface TourDefinition {
  id: string
  version: number
  durationMs: number
  title: string
  stops: TourStop[]
  narration: {
    audioUrl: string
    captions: CaptionCue[]
  }
}
```

### `TourStop`

```ts
interface TourStop {
  id: string
  placeRef: {
    kind: "attraction" | "food"
    name: string
  }
  startMs: number
  durationMs: number
  camera: {
    amap: CameraCue
    offline: CameraCue
  }
  routeEffect: RouteCue
  storyCard: {
    title: string
    summary: string
    showAtMs: number
    hideAtMs: number
  } | null
}
```

### `PersonaDefinition`

```ts
interface PersonaDefinition {
  id: "senior" | "family" | "photography"
  label: string
  weights: Record<string, number>
  curatedPlaceIds: string[]
  localReasons: string[]
}
```

景点数据库 ID 在不同部署中可能变化，因此巡游定义使用稳定的 `{ kind, name }` 引用，不硬编码数据库 ID，也不复制坐标和详情。页面加载已发布地点后，将引用解析为当前 `place_id`；无法解析的可选站点被跳过，经典路线核心站点缺失时禁止启动巡游并给出可读提示。

## 在线与本地场景切换

本地降级场景在尝试高德初始化之前预加载。高德配置、脚本或场景初始化超过 5 秒即视为本轮不可用。

切换步骤：

1. 导演记录当前 `elapsedMs`、活动站点和暂停状态。
2. 在线画面在 450ms 内湖光溶解。
3. 离线适配器根据同一 `TourStop` 和当前进度恢复画面。
4. 音频、字幕、光球和时间轴不中断。
5. 巡游期间即使网络恢复也不自动切回在线场景。
6. 进入自由探索后才显示“在线地图已恢复”操作，由用户决定是否切回。

前端不得缓存或内置高德地图瓦片。离线场景只使用项目自有图片、SVG、CSS 和随构建发布的内容资源。

## 错误处理

| 故障 | 用户体验 | 内部处理 |
| --- | --- | --- |
| 高德配置或脚本失败 | 轻量显示“本地演示模式” | 切换离线适配器 |
| 巡游中在线场景失败 | 画面短溶解后继续当前站点 | 保留导演时钟并恢复离线画面 |
| 路线 API 失败 | 使用当前画像精选路线，可稍后重试 | 不覆盖最后一个稳定路线 |
| AI 超时或失败 | 展示本地推荐理由 | 保留问题与重试入口，不显示原始异常 |
| 本地音频失败 | 继续字幕和光球状态 | 禁止临时调用实时 TTS |
| 页面隐藏 | 自动暂停 | 返回后等待用户继续 |
| 经典路线核心地点缺失 | 禁止启动并给出维护提示 | 记录缺失地点引用，避免运行期崩溃 |

## 无障碍与输入方式

- 所有巡游控制都可通过键盘访问，并具有明确的焦点样式。
- `Space` 只在页面非输入状态下控制巡游，不能拦截输入框空格。
- 所有语音都有同步字幕；讲解卡不依赖声音传递关键信息。
- 状态变化通过可见文字表达，不能只依赖颜色或光球动画。
- 遵循 `prefers-reduced-motion`，关闭大幅镜头运动和脉冲效果。
- 画像选择、应用和撤销按钮具有明确的可访问名称与状态。

## 性能预算

- 本地降级场景进入后 1.5 秒内可操作。
- 高德初始化硬超时为 5 秒。
- 在线与离线场景过渡为 450–500ms。
- 1920×1080 比赛设备目标 60 FPS，主要镜头动画最低不得持续低于 45 FPS。
- 首屏关键本地图片、音频和矢量资源建议不超过 8MB。
- 不为每帧创建 Vue 响应式对象；动画进度使用单一时钟和 `requestAnimationFrame`。
- 连续重播 5 次后不得累积地图实例、监听器或音频对象；垃圾回收后的内存不超过初始稳定值的 15%。

## 测试策略

### 单元测试

- 使用虚拟时钟验证全部时间段和活动站点。
- 验证暂停、继续、跳过、接管、重播和页面隐藏。
- 验证暂停期间 `elapsedMs` 不增长，重播后状态完全重置。
- 验证在线切换离线后仍保持同一站点和进度。
- 验证画像精选路线、推荐理由、确认应用和撤销。

### 场景契约测试

使用同一组命令分别驱动在线场景替身与离线适配器，验证两者都支持初始化、镜头、路线、站点聚焦、探索模式、缩放和销毁。

### 组件测试

- 光球的待机、讲解、思考、可提问和降级状态。
- 讲解卡按时间出现并自动收起。
- 时间轴与导演状态同步。
- 画像切换必须先预览，未经确认不得覆盖当前路线。
- 减少动态效果模式不触发 3D 飞行。

### 浏览器故障测试

分别拦截地图配置、地图脚本、路线 API、AI 和音频请求，验证对应降级路径。视觉验收不得调用真实 AI、实时语音或付费路线服务；完整测试最后单独执行一次真实链路冒烟验证。

### 视口与长时间测试

- 验收视口：1920×1080、1520×856、1440×900。
- 运行完整巡游后连续重播 5 次，检查内存、监听器和音频对象。
- 巡游每个阶段测试暂停、跳过和接管。
- 测试从在线场景切换到本地场景的时间轴连续性。

## 验收标准

- 点击“开始灵境巡游”后不等待真实 AI 即可播放完整经典线。
- 总时长约 78 秒，误差不超过 1 秒。
- 地图是巡游阶段的视觉主体，讲解卡不会长期遮挡核心景观。
- 任意时刻都能暂停、跳过或申请接管。
- 在线切换本地后活动站点一致，字幕和时间轴漂移不超过 250ms。
- 高德、路线、AI 或音频单点失败均不会中断整个演示。
- 三种画像路线均能即时预览、解释变化、确认应用和撤销。
- 真实 AI 失败时自动使用精选路线和本地理由，不显示原始技术错误。
- 减少动态效果模式只执行短淡化和静态取景。
- 三个目标视口无横向溢出、关键按钮遮挡或不可访问区域。
- 连续重播 5 次不产生持续增长的地图实例、事件监听和音频对象。
- 探索页、美食页、反馈页和 AI 导游页不受地图主题与巡游状态影响。

## 实施阶段

### 第一阶段：本规格实施范围

- 分层导演与共享巡游脚本。
- 高德 3D/Loca 在线场景。
- 本地摄影与 SVG 降级场景。
- 78 秒经典巡游、灵境光球、讲解卡和时间轴。
- 自由探索舞台与三种精选画像路线。
- 接入现有路线和 AI 接口，提供超时降级。
- 完整自动化与大屏视觉验收。

### 第二阶段：现场参与

- 手机端定位与路线进度。
- 接近景点后的故事、印章与问答解锁。
- 大屏与手机之间的行程接力方式另行设计。

### 第三阶段：动态智慧规划

- 接入经过确认的实时天气、客流、排队或设施状态数据。
